# Header

A controlled, two-level Cencora application header. It composes `Navbar` for
primary links and persistent section tabs without owning routing, active state,
or product actions. On handset viewports it presents the same navigation in an
internal modal dialog.

## Responsive behavior

- The upper row is 64px tall and always uses 16px of horizontal padding.
- From 768px onward, the space between the logo and the first primary
  navigation item stays fixed at 16px, including at the 1024px breakpoint.
- The section-navigation row is 40px tall. Its horizontal padding is 16px
  below 768px and 40px from the 768px breakpoint onward.
- Below 768px, a 32px hamburger with a centered 18px icon and 3px control
  padding opens the full-screen handset menu. The Cencora logo is reduced in
  the closed header and all header actions remain available.
- The handset menu repeats the controlled primary links and semantically nests
  the section links under the item identified by `sectionParentId`.
- Its selected primary item and selected nested subitem use 40px rows with
  square corners, a 4px brand-colored left border, and the existing light
  brand background. Nested items retain their semantic indentation.
- The section navigation always stays visible as a single horizontally
  scrollable row with no visible scrollbar. It meets the upper row directly
  without a dividing border.
- At 768px and above, the primary navigation appears beside the full-size logo.
  Its items fill the upper header row so the active underline sits directly on
  the boundary with the section navigation.
- If an open handset crosses the 768px breakpoint, it closes automatically.
- Positioning is intentionally external. Add sticky classes through
  `className` only when a consuming page requires them.

## Navigation typography

- Primary navigation uses the existing `body-sm` CDS font-size, font-family,
  and line-height utilities. Inactive items use weight 500 and the active item
  uses weight 700.
- Section navigation uses a 13px font size. Inactive items use weight 500 and
  the active item uses weight 600.
- The handset dialog preserves the same primary and section typography.

## Controlled interfaces

| Prop | Purpose |
|---|---|
| `primaryNavigation` | Items, active ID, accessible label, and callbacks for global navigation |
| `sectionNavigation` | Items, active ID, accessible label, and callbacks for section navigation |
| `sectionParentId` | Required primary item ID under which section links are nested in the handset |
| `actions` | Enabled link/button actions or native disabled icon buttons |
| `mobileMenuLabels` | Optional accessible labels for opening, closing, and naming the handset dialog |
| `logoTo` | Destination for the Cencora logo |
| `className` | Optional positioning or page-level classes for the outer header |

The consumer owns every active ID and callback. An enabled action with `to`
renders a router link; an enabled action without `to` renders a button.
Set `disabled: true` without `to` or `onSelect` when an action must remain
visible but unavailable.

`MobileNavigationDialog` is an internal Header implementation detail and is not
exported as a generic design-system component.

Because `Header` and `Navbar` render React Router links, mount them inside a
Router provider such as `BrowserRouter` or `MemoryRouter`.

## Accessibility

- Give the two navigation landmarks unique `ariaLabel` values.
- Pass a `sectionParentId` that exists in `primaryNavigation.items`; this keeps
  the two navigation levels explicit and predictable.
- Give each action a concise, unique `label`; the icon is decorative and the
  label becomes its accessible name.
- Use the disabled action contract for unavailable actions instead of a
  focusable control with an empty callback.
- The logo link defaults to the accessible name `Cencora home`.
- The hamburger and action controls render at 32px by 32px with 3px padding
  and centered 18px icons. The logo link retains a 44px minimum target, and
  section links fill the specified 40px secondary row. Every interactive
  control retains a visible focus ring.
- Do not use color alone to identify the active section; `Navbar` also renders
  the active underline and `aria-current`.
- The native modal moves initial focus to the close button, keeps background
  controls inert, closes with Escape, and restores focus to the hamburger after
  dismissal. Selecting a destination closes without forcing focus backward.
- The document is scroll-locked while the handset is open.

## Tokens

The component uses existing semantic Tailwind tokens for backgrounds, text,
borders, focus, brand color, spacing, and the hairline shadow. It does not
introduce component CSS or new design-system variables.

Header previews use a light neutral story background so the component remains
easy to inspect independently of the operating-system color scheme.

## Do and don't

- Do pass route-aware data and callbacks from the consuming module.
- Do provide specific destination labels such as `Dashboard` and `Projects`.
- Do keep labels short enough to scan in the horizontal row.
- Do test every real integration at its narrowest supported viewport.
- Don't add routing or section state inside `Header`.
- Don't replace the horizontal row with a disclosure when matching this design.
