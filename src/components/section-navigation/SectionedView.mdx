# SectionedView with Header

`SectionedView` is a headless composition component for an ordered collection
of sections. In this integration, `Header` presents the primary destination and
the active destination's section navigation while the consumer owns both active
IDs and the collection passed to `SectionedView`.

The stories use three controlled groups:

| Primary destination | Associated sections |
|---|---|
| Dashboard | Summary, Demand, Orders |
| Operations | Suppliers, Inventory, Sales |
| Reports | Overview, Performance, Exceptions |

Changing the primary destination replaces the three rendered sections and
activates the new group's first section. That reset is a decision made by the
story harness; neither `Header` nor `SectionedView` performs it internally.

---

## Responsibilities

| Layer | Responsibility |
|---|---|
| `Header` | Render the logo, three primary destinations, current section row, actions, and handset dialog |
| Consumer or harness | Own `activePrimaryId`, `activeSectionId`, group selection, reset policy, destinations, and callbacks |
| `SectionedView` | Render only the supplied section collection and forward active, scroll, semantic, and ref context |
| Navigation controller | Own scrolling, URL/history synchronization, preload, and scroll-spy behavior when a product page needs them |

`Header` and `SectionedView` remain controlled and presentational. Replacing the
section collection does not create routes, scroll the document, or move focus
unless the consumer explicitly implements those behaviors.

## When to use

- Use this composition when each primary Header destination owns a stable
  collection of peer sections.
- Use it when the same active section must drive `aria-current`, rendered
  article state, URL/hash behavior, and scroll coordination.
- Pair it with `useSectionNavigationController` when active state must follow
  scrolling, Back/Forward, or programmatic navigation.

## When not to use

- Do not use it for tab panels that hide inactive content; use an accessible
  tabs component.
- Do not use it for expandable content; use an accordion or disclosure.
- Do not place group-switching or reset policy inside `Header` or
  `SectionedView`; those are consumer decisions.

## Complete controlled implementation

The following pattern matches the story labels, IDs, destinations, accessible
names, reset behavior, and component responsibilities.

```tsx
import { Bell, CircleUserRound, Settings } from "lucide-react";
import {
  useCallback,
  useRef,
  useState,
  type RefCallback,
} from "react";
import { MemoryRouter } from "react-router";
import {
  Header,
  type HeaderAction,
} from "../Header";
import { isUnmodifiedPrimaryClick } from "../Navbar";
import { SectionedView } from "./SectionedView";

type AreaId = "dashboard" | "operations" | "reports";

type SectionId =
  | "summary"
  | "demand"
  | "orders"
  | "suppliers"
  | "inventory"
  | "sales"
  | "overview"
  | "performance"
  | "exceptions";

type ReportSection = {
  slug: SectionId;
  title: string;
};

type NavigationGroup = {
  id: AreaId;
  label: string;
  sections: readonly ReportSection[];
};

const navigationGroups = [
  {
    id: "dashboard",
    label: "Dashboard",
    sections: [
      { slug: "summary", title: "Summary" },
      { slug: "demand", title: "Demand" },
      { slug: "orders", title: "Orders" },
    ],
  },
  {
    id: "operations",
    label: "Operations",
    sections: [
      { slug: "suppliers", title: "Suppliers" },
      { slug: "inventory", title: "Inventory" },
      { slug: "sales", title: "Sales" },
    ],
  },
  {
    id: "reports",
    label: "Reports",
    sections: [
      { slug: "overview", title: "Overview" },
      { slug: "performance", title: "Performance" },
      { slug: "exceptions", title: "Exceptions" },
    ],
  },
] satisfies readonly NavigationGroup[];

const primaryItems = navigationGroups.map(group => ({
  id: group.id,
  label: group.label,
  to: `/${group.id}#${group.sections[0].slug}`,
}));

const actions = [
  {
    id: "notifications",
    label: "Notifications",
    icon: Bell,
    onSelect: () => undefined,
  },
  {
    id: "settings",
    label: "Settings",
    icon: Settings,
    to: "/settings",
    onSelect: () => undefined,
  },
  {
    id: "profile",
    label: "Profile",
    icon: CircleUserRound,
    onSelect: () => undefined,
  },
] satisfies readonly HeaderAction[];

function useSectionRefs() {
  const nodes = useRef(new Map<SectionId, HTMLElement>());
  const callbacks = useRef(
    new Map<SectionId, RefCallback<HTMLElement>>(),
  );

  return useCallback((id: SectionId) => {
    let callback = callbacks.current.get(id);

    if (!callback) {
      callback = node => {
        if (node) {
          nodes.current.set(id, node);
        } else {
          nodes.current.delete(id);
        }
      };
      callbacks.current.set(id, callback);
    }

    return callback;
  }, []);
}

type SectionedDashboardProps = {
  initialSectionId?: SectionId;
  isProgrammaticScrolling?: boolean;
  contentAs?: "main" | "section";
  contentId?: string;
  contentLabel?: string;
};

type NavigationStatusProps = {
  activeGroup: string;
  activeSection: string;
  programmatic: boolean;
};

function NavigationStatus({
  activeGroup,
  activeSection,
  programmatic,
}: NavigationStatusProps) {
  return (
    <div role="status" aria-live="polite">
      <p>Active group: {activeGroup}</p>
      <p>Active section: {activeSection}</p>
      <p>
        Scroll mode: {programmatic ? "Programmatic" : "Manual"}
      </p>
    </div>
  );
}

export function SectionedDashboard({
  initialSectionId = "summary",
  isProgrammaticScrolling = false,
  contentAs = "main",
  contentId,
  contentLabel = "Current area sections",
}: SectionedDashboardProps) {
  const initialGroup = navigationGroups.find(group =>
    group.sections.some(section => section.slug === initialSectionId),
  )!;
  const [activePrimaryId, setActivePrimaryId] =
    useState<AreaId>(initialGroup.id);
  const [activeSectionId, setActiveSectionId] =
    useState<SectionId>(initialSectionId);
  const getSectionRef = useSectionRefs();
  const activeGroup = navigationGroups.find(
    group => group.id === activePrimaryId,
  )!;
  const activeSection = activeGroup.sections.find(
    section => section.slug === activeSectionId,
  )!;
  const sectionItems = activeGroup.sections.map(section => ({
    id: section.slug,
    label: section.title,
    to: `/${activePrimaryId}#${section.slug}`,
  }));

  return (
    <SectionedView
      sections={activeGroup.sections}
      activeId={activeSectionId}
      isProgrammaticScrolling={isProgrammaticScrolling}
      getSectionId={section => section.slug}
      getSectionRef={getSectionRef}
      renderHeader={() => (
        <>
          <Header
            primaryNavigation={{
              items: primaryItems,
              activeId: activePrimaryId,
              ariaLabel: "Primary navigation",
              onSelect: (item, event) => {
                if (!isUnmodifiedPrimaryClick(event)) return;

                const nextGroup = navigationGroups.find(
                  group => group.id === item.id,
                )!;

                setActivePrimaryId(nextGroup.id);
                setActiveSectionId(
                  nextGroup.sections[0].slug,
                );
              },
            }}
            sectionNavigation={{
              items: sectionItems,
              activeId: activeSectionId,
              ariaLabel: `${activeGroup.label} sections`,
              ariaCurrent: "location",
              onSelect: (item, event) => {
                if (!isUnmodifiedPrimaryClick(event)) return;

                setActiveSectionId(item.id);
              },
            }}
            sectionParentId={activePrimaryId}
            actions={actions}
          />

          <h1 className="sr-only">Sectioned dashboard</h1>
        </>
      )}
      renderNavigation={({
        isProgrammaticScrolling: programmatic,
      }) => (
        <NavigationStatus
          activeGroup={activeGroup.label}
          activeSection={activeSection.title}
          programmatic={programmatic}
        />
      )}
      renderSection={(
        section,
        { id, isActive, sectionRef },
      ) => (
        <article
          ref={sectionRef}
          aria-labelledby={`${id}-heading`}
          data-active={isActive}
        >
          <h2 id={`${id}-heading`}>{section.title}</h2>
        </article>
      )}
      contentAs={contentAs}
      contentProps={{
        id: contentId,
        "aria-label": contentLabel,
      }}
    />
  );
}

export function SectionedDashboardExample() {
  return (
    <MemoryRouter initialEntries={["/dashboard#summary"]}>
      <SectionedDashboard />
    </MemoryRouter>
  );
}
```

The primary callback deliberately resets `activeSectionId` to
`nextGroup.sections[0].slug`. A product that should remember one active section
per group would implement a different state policy in the consumer without
changing either shared component.

## Component contracts

- Every ID returned by `getSectionId` must be unique within the supplied
  collection.
- When `sections` is not empty, `activeId` must identify one supplied section.
- Changing primary groups requires updating `sections` and `activeId` in the
  same consumer transaction.
- `renderNavigation` receives the active ID, programmatic state, and current
  ordered collection; it does not own them.
- `renderSection` receives the logical ID, index, active state, scroll state,
  and ref callback for each current section.
- `contentProps` supplies semantic attributes; `contentClassName` supplies
  presentation.

## Styling and tokens

`SectionedView` adds no layout classes, visual styles, or design tokens. Header,
article, status, and content presentation belong to the consumer render
functions.

These previews use the shared light Storybook theme so semantic Navbar text and
hover states stay legible even when the operating system uses dark mode. This
does not change either component's product theme.

## Accessibility

- Give Header's two navigation landmarks distinct names: `Primary navigation`
  and `${activeGroup.label} sections`.
- Use `aria-current="page"` for the active primary link and
  `aria-current="location"` for the active section link.
- Pass the active primary ID as `sectionParentId`; the handset dialog then
  nests the current sections under the correct primary item.
- Keep one page-level `h1`; the stories use the visually hidden heading
  `Sectioned dashboard`.
- Give every article an accessible name by connecting
  `aria-labelledby` to its section heading.
- Preserve native modified-link behavior before updating controlled state.
- Scrolling and keyboard focus are separate concerns. Programmatic scrolling
  does not automatically move focus to an article.
- Keep the horizontal section row width-constrained so overflow remains inside
  the Navbar rather than the document.

## Do and don't

| Do | Don't |
|---|---|
| Keep primary and section active IDs in the consumer | Add routing or group state inside Header |
| Replace sections and reset the active ID together | Pass an active ID that is absent from the new collection |
| Derive Header items and SectionedView articles from the same group | Maintain duplicate navigation and content data |
| Pass the active primary ID to `sectionParentId` | Hard-code handset nesting to one group |
| Attach every supplied `sectionRef` | Discard refs inside `renderSection` |
| Keep labels and article headings consistent | Use visual styling alone to communicate current state |
