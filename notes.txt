# PR Title

[CPR-841] Add controlled dashboard layout and progressive Storybook navigation

## Summary

Adds `StratiumDashboardLayout`, a reusable controlled dashboard shell with configurable primary and secondary navigation.

The accompanying Storybook implementation demonstrates routing, hash synchronization, focus management, progressive lazy loading, real code splitting, preload behavior, dynamic-height scroll correction, responsive navigation, and accessible loading states without introducing fixture pages into production routes.

The branch also improves Header, Navbar, and Typography stories and configures Storybook MSW support for authenticated previews.

## Why

Dashboard modules need a consistent application shell without coupling navigation state, routing, content loading, or scrolling behavior to the layout itself.

This change provides:

- A reusable and type-safe dashboard layout.
- Consumer-defined primary modules and section navigation.
- A reference implementation for routing and progressive section loading.
- Stable, accessible Storybook previews across light-theme environments.
- Better test isolation for stories that depend on authentication or API data.

## Technical Notes

- Adds a controlled `StratiumDashboardLayout` API requiring:
  - `primaryItems`
  - `activePrimaryId`
  - `sectionNavigation`
  - `children`
- Primary navigation IDs and callbacks are inferred from the supplied item collection.
- Existing Stratium navigation is available as an explicit reusable collection but is never applied implicitly.
- The existing dashboard layout remains unchanged.
- Adds seven private Storybook section fixtures loaded through independent dynamic imports:
  - Summary
  - Demand
  - Orders
  - Suppliers
  - Inventory
  - Sales
  - Perfect Order
- The Storybook controller implements:
  - Immediate active-state updates on selection.
  - Route and hash normalization.
  - Back/Forward synchronization.
  - Intent and proximity-based preload.
  - `React.lazy` and `Suspense` fallbacks.
  - Programmatic scrolling with manual-interruption handling.
  - `ResizeObserver` correction when preceding sections change height.
  - Reduced-motion support.
  - A content scrollbar constrained below the sticky Header.
- Demand includes a Storybook-only control for repeatedly appending skeleton groups and validating dynamic-height realignment.
- Story controls configure:
  - Initial primary module.
  - Initial Manage section.
  - Lazy-loading delay.
  - Programmatic scroll motion.
  - Opt-in `play` interactions.
- Embedded Docs previews omit `play` to prevent focus and scroll changes in the documentation page.
- Header and Storybook previews use the light theme consistently.
- Adds `msw-storybook-addon`, the generated service worker, and shared mock handlers so authenticated stories can render in isolation.
- No production routes, fixture pages, migrations, or deployment changes are introduced.
